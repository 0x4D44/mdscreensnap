# Coverage Improvement Plan

## Objective
Increase code coverage of `mdscreensnap` to >98% by refactoring for testability and adding comprehensive unit tests.

## Strategy
The core strategy is **Dependency Injection**. We will move the main application logic from `src/main.rs` to a new `src/lib.rs` and introduce a `Runtime` trait that abstracts all side effects (commands, FS, time).

## Stages

### Stage 1: Architecture Refactoring
**Goal:** Separate pure logic from the binary entry point and introduce the `Runtime` abstraction.
1.  Move `Args`, `run`, and helper functions to `src/lib.rs`.
2.  Create `src/runtime.rs` defining a `Runtime` trait with methods for:
    -   `sleep(duration)`
    -   `exec_command(command, args)`
    -   `write_file(path, content)`
    -   `read_file(path)`
    -   `file_exists(path)`
    -   `is_wsl()`
    -   `open_file(path)`
3.  Implement `RealRuntime` that wraps the standard library and `std::process::Command`.
4.  Refactor `run` to accept `impl Runtime` instead of using global functions.

### Stage 2: Mocking Infrastructure
**Goal:** Create a mock runtime implementation for testing.
1.  Create `MockRuntime` struct in tests.
2.  Implement `Runtime` for `MockRuntime` with:
    -   Call recording (to verify what commands were run).
    -   Canned responses (return specific stdout/stderr for commands).
    -   Virtual file system (simple HashMap for tracking files).

### Stage 3: Testing Core Logic (`run`)
**Goal:** Cover all branches in the `run` function.
1.  **Test Delay:** Verify `sleep` is called when `delay > 0`.
2.  **Test Capture:** Verify the correct screenshot command is "executed" (script generation is already tested, now verify the execution call).
3.  **Test Clipboard:** Verify clipboard command is executed when requested.
4.  **Test No-Save:** Verify temp file creation and cleanup (delete) happens.
5.  **Test Open:** Verify `open_file` is called when requested.
6.  **Test Errors:** Simulate failures (e.g., directory creation fails, command fails) and verify error handling.

### Stage 4: Testing Platform Abstractions
**Goal:** Verify that the platform-specific command generators are correct (even if we don't run them).
1.  Refactor `capture_screenshot_*`, `list_monitors_*` to return the *command string* (or `Command` builder) rather than executing it immediately, or use the `Runtime` to execute.
2.  Since `generate_powershell_script` is already tested, we need to ensure the `Runtime` receives the correct script passed to `powershell`.
3.  Add specific tests for `wsl_to_windows_path` logic (mocking the `wslpath` command execution).

### Stage 5: Cleanup and Verification
1.  Run `cargo llvm-cov` to verify coverage.
2.  Ensure all tests pass on both Windows and Linux (WSL) environments if possible, or use conditional compilation for tests.
